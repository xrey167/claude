# Document Review Checklists

## PRD Review Checklist
- [ ] Problem statement is clear and validated with users/data
- [ ] Goals have specific, measurable success metrics
- [ ] User stories follow INVEST criteria
- [ ] Every functional requirement is testable
- [ ] Non-functional requirements have concrete targets
- [ ] Scope clearly defines what's in AND out
- [ ] Dependencies are identified with owners and risk levels
- [ ] Risks have concrete mitigations
- [ ] Timeline has realistic milestones
- [ ] No jargon or ambiguous terms without definitions

## ADR Review Checklist
- [ ] Context explains WHY, not just WHAT
- [ ] Decision is specific and unambiguous
- [ ] At least 2 alternatives are genuinely considered
- [ ] Pros and cons are honest and balanced
- [ ] Consequences include downsides, not just benefits
- [ ] Effort estimates are realistic
- [ ] References link to related decisions
- [ ] Status is current (not stale "Proposed")

## Technical Spec Review Checklist
- [ ] Links to approved PRD
- [ ] Architecture diagram is clear and current
- [ ] All components have defined responsibilities
- [ ] API design follows conventions (REST/GraphQL)
- [ ] Data model is normalized appropriately
- [ ] Error handling covers all failure modes
- [ ] Security considerations address auth, authz, data protection
- [ ] Testing strategy covers unit, integration, and E2E
- [ ] Migration plan is zero-downtime capable
- [ ] Rollback plan is documented and tested
- [ ] Open questions are listed and assigned owners

## User Story Review Checklist
- [ ] Follows "As a [role], I want [action], so that [benefit]" format
- [ ] Acceptance criteria use Given/When/Then format
- [ ] Edge cases are identified
- [ ] Dependencies are noted
- [ ] Estimate is relative sized (S/M/L/XL)
- [ ] Priority is assigned (must/should/nice-to-have)
- [ ] Story is small enough to complete in one sprint
